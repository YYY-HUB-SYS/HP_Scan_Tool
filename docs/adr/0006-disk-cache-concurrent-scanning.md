# ADR-0006: 磁盘缓存 + 并发扫描 + 自动清理

## 状态
已接受 (2026-07-16)

## 背景
当前扫描流程将全分辨率图像数据保存在内存中（bytes），限制了并发扫描能力。现代 CPU 8-16 线程完全有能力并发处理多台打印机扫描，瓶颈在于内存占用。

## 决策

### 磁盘缓存架构
- 扫描数据直接写入磁盘缓存，不再全量加载到内存
- 缓存位置：`{用户文档目录}/HP_Scans/.cache/{job_id}/`
- 预览时从缓存文件加载 → 应用曝光 → 缩放到预览尺寸（内存中只有缩略图级别数据）
- 确认保存 → 从缓存复制到最终位置 → 清除该 job 缓存
- 取消 → 直接清除缓存

### 并发扫描
- 支持多台打印机同时扫描（真正并发，方案 C）
- 每个扫描任务独立缓存子目录，互不干扰

### 缓存清理策略
- 缓存上限：可配置，默认 1024MB（单位统一 MB）
- 强制清理触发线：上限的 95%（默认 972.8MB）
- 清理量：每次自动清除 150MB
- 清理顺序：FIFO（最旧的缓存文件优先删除）
- 扫描前检查：每次写入缓存前检查当前大小，接近触发线就自动清理
- 启动时兜底：清理超过 24 小时的残留缓存（防崩溃遗留）

### 曝光处理流程（磁盘缓存版）
1. 扫描 → 原始数据写入缓存文件（全分辨率、未处理）
2. 预览刷新 → 从缓存加载 → apply_exposure → thumbnail → 显示
3. 确认保存 → 从缓存加载原图 → apply_exposure（最终参数）→ 写入目标文件 → 清除缓存

## 理由
- 内存占用从「N 台 × 全分辨率图像」降为「N 台 × 缩略图」，并发无压力
- 磁盘 I/O 不是瓶颈：扫描仪硬件 5-10 秒/页，磁盘写入 < 0.1 秒
- FIFO 清理策略简单可靠，不需要用户手动管理
- 24 小时兜底清理防止崩溃后缓存残留
