# ADR-0004: 多页保存支持自定义分组

## 状态
已接受 (2026-07-16)

## 背景
多页 ADF 扫描的保存策略。用户选了 PDF 格式扫了 20 页，可能需要灵活分组。

## 决策
- PDF 格式默认合并为单个多页 PDF
- 用户可选择保存为独立文件（page_001.jpg, page_002.jpg...）
- PDF 格式支持自定义页面分组：用户可指定页码范围，每组生成一个独立 PDF
  - 示例：20 页 → [1-5] [6-18] [19-20] 生成 3 个 PDF 文件

## 理由
- PDF 默认合并符合大多数用户直觉（一份文件 = 一个 PDF）
- 自定义分组覆盖实际办公场景：一份合同 20 页，前 5 页是封面+目录，中间是正文，最后是附件
- 分组信息在 PreviewDialog 的翻页界面中自然表达：用户标记分割点即可

## UX 草案
PreviewDialog 多页模式下：
- 缩略图列表展示所有页面
- 页面之间可插入「分割线」标记分组
- 每个分组可单独命名（可选）　**✅ 已实现**（2026-10-21，提交 `8701b60`）—— 保存前弹出**独立模态窗口** `SaveGroupNameDialog`（每组一行：组标签 + 名字输入框 + 最终文件名预览）；组名经 `save_manager.sanitize_group_name` 净化（Windows 非法字符 / 路径分隔符 / 控制字符 / 结尾的点与空格 / 超长）后**落进产物文件名**（`{base}_{组名}.pdf` / `{base}_{组名}_{seq:03d}.ext`）。★ **留空 ⇒ 回落到组号** ⇒ 文件名与改造前逐字节一致；**单组不弹窗**。★ 入口做成**独立窗口**而不是往预览里塞输入框，是为了守住「不改 UI 样式与布局」红线
- 保存时按分组生成文件，文件名自动附加序号
