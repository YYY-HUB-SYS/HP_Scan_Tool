> 依据：`docs/audit/2026-10-20_审计发现修复计划_v1.0.md` 批次 2
> 目标：让"选 PDF"真正能用，并为后续的自动纠偏、双面合并、断点续扫铺好页元数据地基

---

## 0. 为什么必须做

用户的核心场景是"ADF 一次吃 40 张，400 页文档分 10 次扫，最后输出**一个完整 PDF**"。当前状态下这条路**根本走不通**：

| 缺陷 | 现象 | 实测 |
|------|------|------|
| **C-1** | 打印机直出 PDF 字节 → `save_manager` 按图片处理 → 单页抛 `UnidentifiedImageError`、多页 `except` 吞异常 → `saved_files=[]` → 对话框静默关闭 | **提示保存成功，产出 0 个文件** |
| **I-11** | `save_pages` 用 `save_all=True, append_images=[...]` → 全部页一次性载入内存 | 300dpi 约 26MB/页 → **400 页 ≈ 10.4GB**，保存阶段必然 OOM |
| **I-13** | 单页 PDF 走 `_save_a4_pdf`（A4 画布归一），多页 PDF 走 `images[0].save(..., save_all=True)`（**不归一**） | 同一次扫描，**单页与多页的 PDF 页面尺寸不一致** |
| **I-9** | `scan_coordinator._apply_a4_crop` **原地改写缓存文件** | 扩展名撒谎（`.png` 文件头变 `ffd8ffe0`），**原件不可恢复** → 纠偏角无法回溯重算 |

**I-9 是自动纠偏功能的前置条件**：A4 画布归一会引入额外倾斜，若在归一后才算角度，算出来的是"归一后的角度"而非"原稿角度"，纠偏就无从谈起。

---

## 1. 决策：统一为「打印机只出图片，PDF 本地合成」

### 1.1 现状的根因

```
请求层：选 PDF → FORMAT_MIME["pdf"] = "application/pdf" → 打印机直出 PDF 字节
落盘层：save_manager 一律按图片处理 → Image.open(PDF 字节) → UnidentifiedImageError
```

**请求层与落盘层对"PDF"的理解不一致**，这是 C-1 的根源。

### 1.2 方案 A（采用）：请求层与落盘层统一

**打印机永远出图片，PDF 在本地合成。**

| | 方案 A（采用） | 方案 B（否决） |
|---|---|---|
| 做法 | 选 PDF 时请求层也请求 `image/jpeg`；PDF 在本地合成 | 保留打印机直出 PDF；落盘层做 PDF→PDF 合并 |
| C-1 | 消失 | 需专门处理 |
| I-13 | 消失（本地统一 A4 画布） | 仍需处理 |
| I-11 | 可流式解决 | 可流式解决 |
| 代价 | 打印机不再直出 PDF（矢量文字丢失）；JPEG 有损 | 保留直出 PDF |
| 新依赖 | `pypdf`（纯 Python，无编译） | `pypdf` |

**选 A 的理由**：文档扫描场景的 PDF 本来就是图片页，300dpi JPEG 质量 95 的损失可忽略；而 A 一次性消掉三个问题，并让"选 PDF"与"选 JPG"走**同一条**代码路径——I-13 的根因就是这两条路径行为不一致，后续的分组保存、双面 odd/even 合并、续扫合并全都依赖它们统一。

### 1.3 请求层的格式映射

在 `escl_engine.py` 里把"用户选择的输出格式"拆成两件事：**向打印机请求什么** 与 **落盘成什么**。

```python
# 用户选择的输出格式 → (向打印机请求的 MIME, 落盘扩展名)
REQUEST_FORMAT = {
    "jpg":  ("image/jpeg", "jpg"),
    "jpeg": ("image/jpeg", "jpg"),
    "png":  ("image/png",  "png"),
    "tiff": ("image/tiff", "tiff"),
    "tif":  ("image/tiff", "tiff"),
    "pdf":  ("image/jpeg", "pdf"),   # 请求图片，落盘时本地合成 PDF
}
```

`_create_scan_job` 里把现在的：

```python
    mime = FORMAT_MIME.get(output_format.lower(), "image/jpeg")
    ext = MIME_EXT.get(mime, output_format)
```

改为：

```python
    mime, ext = REQUEST_FORMAT.get(output_format.lower(), ("image/jpeg", "jpg"))
```

**注意**：`FORMAT_MIME` 与 `MIME_EXT` 保留不动（`cli.py`、显示逻辑可能引用），只是**扫描请求**改用 `REQUEST_FORMAT`。

**行为对照表（改完后必须成立）**

| 用户选 | 向打印机请求 | 落盘扩展名 | 落盘产物 |
|--------|--------------|-----------|----------|
| jpg | image/jpeg | jpg | JPEG |
| png | image/png | png | PNG |
| tiff | image/tiff | tiff | TIFF |
| **pdf** | **image/jpeg** | **pdf** | **本地合成的 PDF（A4 画布）** |

## 2. I-11：流式 PDF 合成

### 2.1 现状

`save_manager.save_pages` 的 PDF 分支：

```python
            images[0].save(pdf_path, "PDF", save_all=True, append_images=images[1:])
```

`images` 列表里装着**全部页的 PIL Image 对象** ⇒ 内存 = 全部页之和。

### 2.2 改法：两阶段流式

```
阶段一（逐页，内存只占一页）：
    for each page_spec:
        with Image.open(cache_path) as src:
            img = A4 画布归一(src)          # 复用 _save_a4_pdf 的画布逻辑
            img.save(tmp_page_pdf, "PDF", resolution=dpi)   # 单页 PDF 临时文件

阶段二（流式合并，内存只占一页）：
    writer = PdfWriter()
    for tmp in tmp_page_pdfs:
        writer.append(tmp)                  # 逐页 append，不全量载入
    with open(final_path, "wb") as f:
        writer.write(f)
```

**依赖**：`pypdf`（纯 Python，MIT/BSD，无编译）。加进 `requirements.txt`。

### 2.3 A4 画布归一必须复用同一份逻辑

现在的 `_save_a4_pdf(img, path, dpi)` 是"把图放到 A4 画布上再存 PDF"。流式方案需要**先归一、再逐页存单页 PDF**。

**要求**：把"A4 画布归一"抽成一个可复用的函数（例如 `_a4_canvas(img, dpi) -> Image`），让：
- 单页 PDF 走它
- 多页 PDF 的每一页也走它

这样单页与多页的 PDF 页面尺寸就一致了（I-13 消失）。

**临时文件**：阶段一的单页 PDF 临时文件放在**系统临时目录**（`tempfile.mkdtemp()`），用完即删；**不要**放缓存目录（会被 eviction 清掉，也会污染缓存大小统计）。

## 3. I-9：A4 裁剪不得覆盖原件 → 页元数据模型

### 3.1 现状

`scan_coordinator._apply_a4_crop(cache_path, dpi)` 读缓存文件 → 算 A4 裁剪 → **把结果写回同一个路径**。后果：扩展名撒谎、原件不可恢复。

### 3.2 改法：取消扫描后的即时裁剪，统一到落盘时做

- **删除** `scan_coordinator._apply_a4_crop` 的调用（以及该方法本身）
- 缓存里**永远保留原始扫描件**，不做任何像素改动
- A4 归一在 `save_manager` 落盘时统一进行（与 §2.3 同一份逻辑）

**副作用（可接受，且更合理）**：预览对话框显示的是**原图**（可能带扫描白边），而不是 A4 裁剪后的图。最终 PDF 才是 A4 尺寸。这是扫描软件的常态。

### 3.3 页元数据模型（自动纠偏的前置）

纠偏角、手动旋转角、原始尺寸这些信息**必须落盘**，否则续扫/双面/大批量场景下全部丢失（审计确认：现在旋转角只存在 GUI 内存的 `self._rotations`，尺寸不落盘，纠偏角根本没有）。

**新增** `page_meta.py`：

```python
"""
页面元数据 — HP Scan Tool v4.0
记录每页的原始几何与处理参数，使纠偏/续扫/双面/大批量合并可回溯。
"""

import json
import os
from dataclasses import asdict, dataclass, field
from typing import Optional


@dataclass
class PageMeta:
    """单页元数据。cache_path 指向**永不修改**的原始扫描件。"""
    cache_path: str
    width: int
    height: int
    manual_rotation: int = 0        # 用户手动旋转 0/90/180/270
    deskew_angle: float = 0.0       # 自动纠偏角（度），批次 4 使用
    a4_normalized: bool = False     # 落盘时是否做过 A4 画布归一
    crop_rect: Optional[tuple] = None   # 自动裁边框


class PageMetaStore:
    """按 job 持久化页元数据（原子写：.tmp + os.replace）"""

    def __init__(self, cache_root: str):
        self._path = os.path.join(cache_root, "page_meta.json")

    def load(self) -> dict:
        try:
            with open(self._path, "r", encoding="utf-8") as f:
                data = json.load(f)
            return data if isinstance(data, dict) else {}
        except (FileNotFoundError, json.JSONDecodeError):
            return {}

    def save(self, metas: dict) -> None:
        tmp = self._path + ".tmp"
        os.makedirs(os.path.dirname(self._path), exist_ok=True)
        with open(tmp, "w", encoding="utf-8") as f:
            json.dump(metas, f, ensure_ascii=False, indent=2)
        os.replace(tmp, self._path)

    def set_page(self, job_id: str, page_no: int, meta: PageMeta) -> None:
        metas = self.load()
        metas.setdefault(job_id, {})[str(page_no)] = asdict(meta)
        self.save(metas)

    def get_job(self, job_id: str) -> dict:
        return self.load().get(job_id, {})

    def remove_job(self, job_id: str) -> None:
        metas = self.load()
        if job_id in metas:
            del metas[job_id]
            self.save(metas)
```

**要求**：
- `scan_coordinator.run_scan_sync` 在写完每页缓存后，**记录该页的 `PageMeta`**（原始 width/height + cache_path）
- `save_manager` 在保存后 `remove_job` 时**一并清理**该 job 的元数据
- 元数据文件放在**缓存根目录**（`{cache_root}/page_meta.json`），不放在 job 子目录里（避免被 eviction 当 job 目录处理）
- **注意**：`cache_manager._evict_oldest_jobs_locked` 会遍历缓存根下的**目录**并按目录大小算 eviction 占用；`page_meta.json` 是文件，不会被误算成 job 目录，但要确认 `_cache_size_bytes` 统计它不影响逻辑（它只是个几 KB 的文件）

**本批次只落地模型与写入，纠偏角字段先留 0**（批次 4 用）。

## 5. 验收标准

- 选 PDF 的完整链路可用：扫描 → 缓存 → 预览 → 保存 → 得到可打开的 PDF
- 单页与多页 PDF 页面尺寸一致
- 400 页规模不 OOM（用 mock 或较小页数验证内存不随页数线性增长；**真机 400 页实测留到批次 4**）
- 缓存里的原始扫描件**字节未被修改**
- 页元数据落盘、可读、可清理
- `pytest tests/ -v` 无失败；原有测试一条不退化
- `requirements.txt` 增加 `pypdf`

## 6. 风险与未决项

| 风险 | 说明 | 缓解 |
|------|------|------|
| 打印机直出 PDF 能力被弃用 | 部分机型支持直出矢量 PDF，改成请求 JPEG 后 PDF 由本地合成 | 文档扫描场景无影响；若后续需要矢量 PDF 再单独评估 |
| `pypdf` 是新依赖 | 纯 Python，MIT/BSD 许可，无编译 | CI 已加门禁，装不上会立刻红 |
| 取消即时 A4 裁剪后，预览尺寸与最终 PDF 不一致 | 预览显示原图 | 扫描软件常态；如需一致可在预览里显示"输出将归一为 A4"的提示 |
| 页元数据文件与 eviction 的交互 | `page_meta.json` 在缓存根 | 确认它不会被当成 job 目录被删除或影响大小统计 |

**未决（等用户确认）**：是否保留"打印机直出 PDF"作为高级选项（默认关闭）。
