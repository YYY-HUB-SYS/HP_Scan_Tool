## 1. 背景

### 1.1 这个软件是干什么的

HP Scan Tool 是**面向 HP 网络打印机的 Windows 桌面扫描客户端**，用来替代需要装驱动的 HP 官方扫描客户端。核心价值是**免驱**：通过 eSCL/AirScan 协议（HTTP + XML）直接与打印机通信，插上电网线就能把纸质文件扫成 jpg/pdf 落到本机，不依赖 HP Smart 或任何厂商驱动。

产品定位上有三个已确认的特征：

- **多打印机、多部门场景**：支持自定义名称、按设备 IP 独立保存扫描参数、打印机列表排序与禁用、按 IP 记忆上次选中设备。这些都不是单人单机需求。
- **明确的职责边界**："HP Scan Tool 仅用于扫描"。曝光矫正、预设、扶正等图像后处理已于 v3.3（2026-07-19）剥离至独立工具 DocFix，代码留在 `_docfix_reserve/` 备查。本项目只负责"把纸变成文件"，不管文件好不好看。
- **主要使用动作是电脑端一键扫描**。监听模式（人站在打印机前按面板触发）虽然实现完整但**实际很少使用**，本轮不作为改动重点。

### 1.2 为什么现在要改

2026-10-20 的接管审计发现两个层面的问题：

**功能缺陷（P0）**：`cli.py:102` 写作 `elif args.mdns-only:`，argparse 的 dest 是 `mdns_only`。该 elif 表达式无条件求值，导致 `cli.py discover` 整条命令 100% 抛 `AttributeError`（默认双协议路径、`--format json`、`--mdns-only` 三种调用全部崩溃，仅 `--wsd-only` 因走第一分支幸免）。已实测复现。现有 60 个测试全绿却抓不到，因为 `tests/test_cli.py` 只测 argparse 解析，从不调用命令体。

**结构问题**：`ScanCoordinator.execute_scan_to_cache` 无任何调用方，是死代码；GUI 侧 `hp_scan_gui_pyside.py` 另有一套完整但不等价的扫描流程。两套流程在 ADF 探测方式、`cancel_event` 透传、A4 裁剪上都不一致。GUI 主文件已达 2890+ 行。

### 1.3 本次改造的真实目的

**不是为了架构漂亮，是为了"结构正确性 + 可测性"**：

1. 消除"两套扫描流程"，让 ADF 探测、取消、缓存、裁剪、保存各只有一处实现
2. 让扫描流程**可单元测试**——目前 GUI 里的流程无法离线验证，只能靠真机
3. 补上"命令体零覆盖"的测试缺口
4. 顺手修掉多页分组保存的文件名覆盖 bug

**不改变**产品定位、不改变用户操作路径、不改变任何用户可见的功能特性。

## 3. 架构设计

### 3.1 目标结构

```
hp_scan_gui_pyside.py (GUI 层 — PySide6)
  ├── ScanApp              — 只订阅协调器信号，不自己起线程、不自己调引擎
  ├── PreviewDialog / MultiPagePreviewDialog  — 纯 UI 交互，保存时调 save_manager
  └── HistoryDialog / ScannerCard / ImageViewer / AnimatedButton / LoadingDialog
        │ 信号订阅
        ▼
scan_coordinator.py (业务层 — 引入 PySide6.QtCore)
  └── ScanCoordinator(QObject)
        ├── scan_started / scan_progress / scan_finished / scan_failed / scan_cancelled
        ├── start_scan(scanner, params) -> job_id     # 异步壳，线程池
        ├── run_scan_sync(scanner, params) -> ScanResult  # 同步可测体
        ├── resolve_source(scanner, requested) -> str     # ADF 探测唯一入口
        ├── cancel_scan(job_id)
        └── save_pages(...) -> list[str]                 # 委托 save_manager
        ▼
save_manager.py (I/O 层 — 纯 Python，不依赖 Qt)
  └── save_pages(...) / save_single(...) / copy_to_extra_dirs(...) / write_history(...)

escl_engine.py / wia_engine.py / wsd_engine.py (协议层)
cache_manager.py / history_manager.py / profile_manager.py (I/O 层)
```

### 3.2 为什么协调器可以引入 Qt

现有分层原则是"业务层不依赖 GUI 框架"，本设计**有意放宽**到"业务层只依赖 `QtCore`，不依赖 `QtWidgets`"：

- `QtCore` 的 `QObject` / `Signal` / `QThreadPool` 不需要 `QApplication`，不创建任何窗口
- 协调器不 import 任何 `QtWidgets` 类，GUI 专属表现（状态栏、进度条、弹窗）全部留在 GUI 层
- `cli.py` 不 import `scan_coordinator`（它只依赖 `escl_engine` / `wsd_engine` / `history_manager`），**CLI 模式不受 Qt 依赖影响**
- 单测协调器需要 `PySide6`，CI 的 `pip install -r requirements.txt` 已包含，无额外门禁成本

### 3.3 线程模型

- 协调器持有 `QThreadPool(max_thread_count=4)`，每个扫描任务是一个 `QRunnable`
- 任务体在工作线程执行，**信号从工作线程 emit**；Qt 对跨线程连接自动使用 QueuedConnection，槽在 GUI 主线程执行
- 协调器不自己加锁；`cache_manager` 与 `history_manager` 内部已有各自的锁
- `run_scan_sync` 是同步方法，单测直接调用它即可验证全部业务分支，不需要事件循环

### 3.4 取消

- `cancel_event` 从 GUI 移到协调器：`self._cancel_events: dict[str, threading.Event]`
- `cancel_scan(job_id)` 设置对应 Event，引擎侧 `execute_scan` / `execute_multipage_scan` 已经支持 `cancel_event` 参数
- **修正既有缺陷**：协调器原来调用引擎时没有透传 `cancel_event`，取消实际上不生效

## 4. 接口契约

### 4.1 `ScanResult`（`scan_coordinator.py` 内定义）

```python
@dataclass
class ScanResult:
    job_id: str          # 缓存任务 ID
    ext: str             # 实际扩展名 (jpg/png/pdf/tiff)
    page_count: int      # 页数
    cached_paths: list[str]   # 每页缓存文件路径，按页序
    output_path: str     # 目标输出路径（尚未落盘）
    source: str          # 实际使用的来源：Platen / Feeder
    adf_detected: bool   # 是否探测到输稿器有纸
```

### 4.2 `ScanCoordinator` 信号

| 信号 | 载荷 | 触发时机 |
|------|------|----------|
| `scan_started` | `str` (job_id) | 任务入队后 |
| `scan_progress` | `str` (job_id), `str` (msg), `int` (page) | 多页扫描每取到一页 |
| `scan_finished` | `str` (job_id), `object` (ScanResult) | 扫描+缓存+裁剪全部完成 |
| `scan_failed` | `str` (job_id), `str` (error) | 引擎异常 |
| `scan_cancelled` | `str` (job_id) | 取消事件触发 |

### 4.3 `ScanCoordinator` 方法

```python
def start_scan(self, scanner, params) -> str            # 异步，返回 job_id
def run_scan_sync(self, scanner, params) -> ScanResult   # 同步，可单测
def resolve_source(self, scanner, requested) -> tuple[str, bool]
def cancel_scan(self, job_id) -> None
def shutdown(self) -> None                               # 停线程池，GUI closeEvent 调用
```

`params` 字段：`resolution` / `color_mode_ui` / `output_format` / `source`（UI 文本）/ `duplex` / `output_dir`。

`resolve_source` 返回 `(实际来源, 是否探测到输稿器有纸)`：

| 设备 has_adf | 用户请求 | 探测结果 | 实际来源 |
|--------------|----------|----------|----------|
| False | 任意 | 不探测 | Platen |
| True | 任意 | `get_scanner_status` → `adf_loaded=True` | Feeder |
| True | 任意 | `adf_loaded=False` | Platen |

ADF 探测**默认常开**，但只对具备 ADF 能力的设备发起请求——没有 ADF 的设备本来也探测不出结果，不产生任何副作用。与改造前 GUI 行为一致（手动选 Feeder 但设备无 ADF 能力 → 回退 Platen）。

### 4.4 `save_manager.py` 接口

```python
def save_pages(
    job_id: str,
    ext: str,
    output_path: str,
    page_specs: list[tuple[str, int]],   # [(缓存文件路径, 旋转角度), ...]
    groups: list[list[int]],              # 对 page_specs 的索引分组
    extra_dirs: list[str],
    device_name: str,
    device_ip: str,
) -> list[str]                            # 返回实际落盘的文件路径
```

职责（合并原四处重复代码）：

1. 按 `groups` 逐组落盘
2. 旋转角度非 0 时用 PIL 旋转后重编码，否则直接 `shutil.copy2`
3. 复制到 `extra_dirs` 列表中的每个额外目录
4. `cache_manager.remove_job(job_id)` 清缓存
5. `history_manager.append(...)` 写历史

**命名规则修正（B4）**。分两种情况，规则不同：

*只有一组*（无分组）—— **保持现有文件名不变**，用户已习惯的产物命名不受影响：

| 格式 | 文件名 |
|------|--------|
| PDF | `{base}.pdf` |
| 其他 | `{base}_001.ext`、`{base}_002.ext`（组内连续编号） |

*有多组*（用户插了分割线）—— 组间必须不覆盖，按 `docs/tickets.md` T6：

| 格式 | 第 N 组（N 从 1 起）文件名 |
|------|---------------------------|
| PDF | `{base}_{N:03d}.pdf`，如 `{base}_001.pdf`、`{base}_002.pdf` |
| 其他 | `{base}_{N:03d}_{组内序号:03d}.{ext}`，如 `{base}_001_001.jpg`、`{base}_002_001.jpg` |

多组场景下组号必带、组内序号照旧；单组场景不带组号。两种规则不会互相误读。

## 5. 数据流

### 5.1 扫描（改造后）

```
用户在 GUI 点"扫描"
  → _start_scan 组装 params、调 coordinator.start_scan()
  → 协调器入队 QRunnable
  → [工作线程] run_scan_sync:
        resolve_source(scanner, params.source)      # ADF 探测
        execute_scan / execute_multipage_scan       # 引擎，透传 cancel_event
        cache_manager.write_page(...)               # 每页落缓存
        A4 裁剪（crop_to_a4）                       # 居中裁剪，不超过原图
        → ScanResult
  → emit scan_finished(job_id, result)              # 自动排队回主线程
  → GUI 槽：弹 PreviewDialog / MultiPagePreviewDialog（或直接保存）
  → 用户确认 → save_manager.save_pages(...)         # 落盘 + 复制 + 清缓存 + 写历史
  → os.startfile 打开文件夹
```

### 5.2 失败与取消

- 引擎抛异常 → 协调器捕获 → `emit scan_failed` → GUI 显示错误弹窗并重置 UI
- 取消 → `cancel_event` 置位 → 引擎返回 `(None, ext)` / `[]` → 协调器 `emit scan_cancelled` → GUI 重置 UI，**不弹预览**
- 取消时已写入缓存的页面由 `cache_manager` 的启动清理机制回收（`stale_hours` 默认 24h），不立即删除，避免误删

## 6. 错误处理

| 场景 | 处理 |
|------|------|
| 设备无 eSCL 服务 | `probe_escl` 返回 None → 设备卡片标记离线，不进入扫描流程 |
| 能力查询失败 | `fetch_capabilities` 已内建回退（从 ScannerStatus 探测 ADF），扫描用默认参数 |
| 创建 ScanJob 失败 | 引擎抛 `RuntimeError` → `scan_failed` → GUI 弹错误 |
| 扫描超时 | 引擎抛 `RuntimeError("扫描超时…")` → 同上 |
| HTTP 410（数据过期） | 引擎抛 `RuntimeError("扫描数据已过期…")` → 同上 |
| ADF 探测请求失败 | 捕获后保持用户选择的来源，不中断扫描（沿用现有 `logger.debug` 容错策略） |
| 缓存写入失败 | `cache_manager.write_page` 抛 OSError → `scan_failed` |
| 保存时图片损坏 | `save_manager` 内单页 try/except 跳过该页，其余页照常落盘 |
| 额外目录不可写 | 单目录 try/except 跳过，主产物不受影响 |

错误处理原则不变：**主流程失败必须让用户看见**（弹窗 + 状态栏），**旁路失败静默降级**（额外目录、单页损坏）。
