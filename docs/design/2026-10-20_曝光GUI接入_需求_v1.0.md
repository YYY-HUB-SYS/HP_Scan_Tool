## 1. 先定案：预设数据结构

**ADR 0008 写的是** `{name, mode, brightness, contrast, gamma, shadows, highlights, r_gain, g_gain, b_gain}`
**代码实际用的是** `{name, mode, brightness, contrast, gamma, shadows, highlights, channel_gains: [r,g,b], builtin: bool}`

**决策：以代码为准（`channel_gains` 数组 + `builtin` 字段），订正 ADR 0008。**

理由：代码是 2026-07 同期实现且可运行；ADR 是设计稿。为迁就文档去改能跑的代码不划算。`builtin` 字段是实现里用来区分"内置不可删"的，ADR 漏写了，补上。

**要求**：
1. 改 `docs/adr/0008-exposure-enhancement.md` 里的预设数据结构段落，与代码一致，并加一句"2026-10-20 订正：实现采用 `channel_gains` 三元素数组 + `builtin` 标记"
2. 顺手删掉 `exposure.py` 里的死函数 `_stretch_channel()`（stage 1 报告指出：Step 5 自动拉伸已移除，函数体留着没用）

## 2. `save_manager` 侧：接受曝光参数

**依赖批次 2**：批次 2 正在重写 `save_manager` 的 PDF 路径。本阶段**不要**与它抢同一个文件——**在批次 2 完成后再改**。

**接口约定**（批次 2 完成后实施）：

```python
save_manager.save_single(cache_path, ext, output_path, rotation=0,
                          extra_dirs=None, job_id=None,
                          device_name="", device_ip="",
                          exposure=None) -> str
# exposure: dict | None，形如
#   {"mode": "auto"|"manual",
#    "brightness": int, "contrast": int, "gamma": float,
#    "shadows": int, "highlights": int,
#    "channel_gains": (r, g, b)}

save_manager.save_pages(job_id, ext, output_path, page_specs, groups,
                        extra_dirs=None, device_name="", device_ip="",
                        exposure=None) -> list
```

**应用位置**：在 `_write_image` / PDF 合成**之前**对图像应用 `apply_exposure`。

**关键点**：
- `exposure=None` 或 `mode="off"` ⇒ 行为与现在完全一致（向后兼容）
- 曝光在 **A4 画布归一之前**还是之后？**之前**——A4 归一会把图放到白底画布上，曝光（尤其去灰底）应该作用在原图上
- 多页 PDF：每一页都应用同一份曝光参数（第一版是**文档级**参数，不是页级）
- 手动模式与 auto 模式**互斥**：`mode="auto"` 时忽略 brightness/contrast 等手动参数（`apply_exposure` 本身就这么实现）

## 3. GUI 侧：预览时实时调参

### 3.1 加在哪

**`PreviewDialog`（单页）与 `MultiPagePreviewDialog`（多页）都要能调曝光。**

多页预览里调一次曝光 = 作用于全部页（文档级参数）。

### 3.2 UI 元素

在预览对话框底部加一个**曝光工具条**（可折叠，默认收起以免挤占预览空间）：

```
曝光：[关闭 ▾]  预设：[文字增强 ▾]              [保存当前为预设] [删除预设]
手动参数（仅"手动"模式可用）：
  明暗  [-100 ──●──── 100]    对比度 [-100 ──●── 100]
  伽马  [0.1 ──────●─ 3.0]    阴影   [-100 ─●── 100]
  高光  [-100 ───●── 100]      R[0.5─●─1.5] G[0.5─●─1.5] B[0.5─●─1.5]
```

- 模式三选一：`关闭` / `自动`（去灰底）/ `手动`
- 预设下拉：4 个内置 + 用户自定义，选中即套用该预设的全部参数
- "保存当前为预设"：弹一个输入框取名，存为用户预设
- "删除预设"：仅对用户自定义预设可用（内置的 `builtin=True` 不可删）

### 3.3 实时预览

参数变化 ⇒ 重新 `apply_exposure` ⇒ 更新 QPixmap。

**性能处理**：
- `manual` 模式 0.022 秒 ⇒ 直接同步重算，无感
- `auto` 模式 0.37 秒（全分辨率）⇒ 同步重算会让 UI 卡一下
  - **要求**：auto 模式下重算**放在工作线程**（`threading.Thread`），完成后回主线程更新 QPixmap
  - **必须复用批次 3 引入的跨线程 UI 投递机制**（`self._post_ui(...)` / `_ui_post` 信号）——不要用 `QTimer.singleShot`（那在工作线程里不触发，这是已修的 Critical）
  - 切换参数时**丢弃过期的计算结果**（用递增的 token 或比较参数快照，避免旧结果覆盖新结果）
  - 手动模式下如果用户拖动滑块很频繁，也要防抖（建议 200ms）

**与手动旋转的交互**：曝光在旋转之前还是之后应用？**先曝光后旋转**（曝光作用于原始像素，旋转只是几何变换）。

### 3.4 保存时应用

- 用户点"保存" ⇒ 把当前曝光参数传给 `save_manager.save_single` / `save_pages`
- **直接保存模式**（批次 3 刚接上的 `direct_save_val`）也要应用曝光
- 历史记录里可以带上曝光参数（`format` 字段旁加一个 `exposure` 键），便于追溯

## 4. 测试要求

新建 `tests/test_exposure_integration.py`：

1. `save_manager.save_single(..., exposure={"mode": "manual", "brightness": 50})` ⇒ 产物的像素**确实比不加曝光时更亮**（用 `ImageChops.difference` 断言非零）

## 6. 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| auto 模式 0.37 秒/页 × 400 页 = 148 秒 | 大批量扫描时曝光很慢 | 批量场景提示"批量扫描建议用手动模式或关闭"；后续可加"仅对预览应用、落盘不应用"的开关 |
| 曝光与手动旋转、A4 归一的顺序 | 顺序错了会破坏效果 | 固定为 **曝光 → 旋转 → A4 归一**，并用测试锁死 |
| 工作线程重算的竞态 | 旧结果覆盖新结果 | 参数快照/token 校验，过期结果丢弃 |
| `channel_gains` 与 ADR 不一致 | 集成时按错字段实现 | 本阶段先订正 ADR（见 §1） |
