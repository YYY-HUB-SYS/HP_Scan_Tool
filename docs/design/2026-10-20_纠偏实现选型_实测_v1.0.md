## 0. 结论先说

**不用 deskew 库，自己实现纯 PIL 投影法。**

理由（一句话）：deskew 与自实现投影法**角度输出完全一致**（同一数学），但 deskew **慢 3–13 倍**、**多带 183.7 MB 依赖**，而 EXE 是要发给用户拿去用的单文件。

**EXE 体积：62 MB 保持不变**（自实现零依赖）。

## 2. 决策与理由

| | deskew | fast-deskew-cv | **自实现投影法** |
|---|---|---|---|
| 依赖体积 | +183.7 MB | +~40 MB | **0** |
| 单页耗时（300dpi） | 1.059s | ~0.1s（宣称 9× 快于 deskew） | **0.077s** |
| 空白页假阳性 | 有 | 未验证 | **有（需自己加保护）** |
| 与 deskew 角度一致性 | — | 宣称 8/8 一致 | **实测完全一致** |
| 实现与维护成本 | 零 | 零 | **~60 行，需自己测** |

**选自实现**：EXE 体积是用户能感知的（62MB vs 245MB），速度是批量扫描能感知的（31 秒 vs 404 秒），而角度精度两者相同。唯一代价是要自己实现 + 自己测，但算法本身就是 60 行的投影法，不复杂。

**deskew 保留为可选增强**：若将来需要更高精度（如 ±0.1°），可作为可选依赖引入（`try: import deskew except ImportError:` 降级到自实现），但**不进默认打包路径**。

## 3. 实现规格

### 3.1 算法

标准投影法：旋转二值图 → 算**行投影**（每行墨迹像素数）→ 度量**锐利度**（相邻行和之差的绝对值之和）→ 锐利度最大处即最佳角（文本行被拉平 ⇒ 行间空白对齐 ⇒ 投影边界最锐）。

**搜索策略**：粗搜（步长 2°，范围 ±8°）→ 细搜（在粗搜最优 ±2° 内步长 0.5°）。共约 18 次旋转。

### 3.2 符号约定（**必须写进代码注释并用测试锁死**）

> **2026-10-20 订正**：本节原写「PIL `Image.rotate(angle)` 顺时针为正」是**错的**。
> 实测证据（200×200 图、顶部中央方块）：`rotate(+10)` → 方块质心 x=86.21（**向左移**），
> `rotate(-10)` → x=113.78。⇒ **Pillow 的 `rotate` 是逆时针为正**（与 skimage 一致，
> 与我原先的假设相反）。
> 另：本文档原先给的二值化映射（墨迹=255）配 `fillcolor=255`（填纸白）**自相矛盾** ——
> 旋转出的四角会变成大片假墨迹，实测 0° 页估计偏 0.5°。正确映射是 **墨迹=0 / 纸白=255**。
> 详见 `skew_detect.py` 的实现与 `tests/test_skew_detect.py` 的符号闭环测试。

- 我们的合成/旋转一律用 **PIL `Image.rotate(angle)`**，它是**逆时针**为正
- 投影锐利度最大角 = **真实 PIL 旋转角的相反数**
- 落在**缩略图**上算（`target_width=1000`），实测 300dpi A4 输入 0.111 秒/页（deskew 全尺寸 1.059 秒，快 9.5 倍）；400 页 44.4 秒
- ⇒ `skew_detect.estimate_skew(img)` 直接返回**可施加给 PIL 的纠偏量**（已取过负），调用方**不要再取负**
  - 闭环验证：`rotate(+3)` 的图 ⇒ `estimate_skew` 返回 `-3.0` ⇒ `img.rotate(estimate_skew(img))` 摆正
- 二值化映射：**墨迹=0 / 纸白=255**，与 `fillcolor=255` 自洽

> deskew 官方示例用的是 `skimage.transform.rotate`（**逆**时针），所以它的示例代码直接 `rotate(image, angle)`。我们用 PIL，必须取负。**这是集成时最容易搞错、且错了会把纸转歪的地方。**

### 3.3 性能策略

- **在缩略图上算角度**（目标宽 1000px），不碰全分辨率
- 实测：300dpi A4 输入 → 0.077 秒/页；缩略图算出的角度与全尺寸一致
- 旋转用 `Image.BILINEAR`（不是 BICUBIC，够快且够准）
- 行和统计用 `bin_img.tobytes()` + 切片 `sum()`（C 层切片，比逐像素 Python 循环快两个数量级）

### 3.4 空白/低墨迹保护（**必须有**）

判据建议：**墨迹占比 = 总黑像素数 / 总像素数**，低于阈值（建议 0.5%）判为空白/无文字页 ⇒ **不判角度、不纠偏、不提示**。

依据：真机空白玻璃 std=2.7，几乎全是噪点。若不加这个保护，空白页会被判成歪 10° 并被旋转。

> 噪点较多的扫描件可能墨迹占比也低 ⇒ 阈值需要用**真实扫描件**标定。实施时用几份真实文档 + 空白页各测一遍，定出阈值。

### 3.5 与阈值的配合

| 级别 | 阈值 | 行为 |
|------|------|------|
| 自动纠偏 | 角度 > 0.5° | 静默旋转纠偏 |
| 强提醒 | 角度 > 3°（可配） | 标记该页为"歪" |
| 连续判定 | 连续 3 页都超强提醒阈值 | 弹窗（带该页预览图），可中断续扫 / 继续 / 强制保存 |
| 空白页 | 墨迹占比 < 0.5% | 跳过，不纠偏不提示 |

### 5.3 实现中发现的两个事实错误（原 brief / 本文档写错了）

1. **Pillow 的 `Image.rotate(angle)` 是「逆时针为正」**，不是本文档原先写的"顺时针为正"。
   实测证据：200×200 图顶部中央方块 `rotate(+10)` → 质心 x=86.21（向左移 = 逆时针），`rotate(-10)` → x=113.78。
   ⇒ 下游若按"顺时针为正"写，取负逻辑会反。
2. **二值化映射必须与 `fillcolor` 自洽**：原先给的 `point(lambda p: 255 if p < threshold else 0, mode="1")`（墨迹=255）配 `fillcolor=255`（填纸白）是矛盾的 ⇒ 旋转出的四角变成大片假墨迹，实测 0° 页都偏 0.5°。正确映射是 **墨迹=0 / 纸白=255**。

另有一处实现细节：原先的"平局时偏好小角度"tie-break 会让倾斜页偏 0.5°（投影峰是平的，邻居差 <0.1%）。改为**只保护 0° 情形**后，11 个角度全部 0.000° 误差。

### 5.4 契约（下游按这个用）

### 5.5 仍未闭环的两项

1. **真机文档的墨迹阈值未标定**：现阈值 0.005 只用合成页 + 真机空白玻璃标定过。需几份真机文档复测 `ink_ratio`；若某文档显著低于 0.005 会被误判空白而跳过纠偏，需下调阈值。
2. **真机斜纸的绝对方向需人工验证**：合成图只能验自洽，验不了真机上的绝对方向。需要人工往玻璃上斜放一张纸再扫一次。
3. **噪声页会给出有界但随机的角度**（只靠墨迹占比挡空白页，未做角度置信度指标），后续可加。
